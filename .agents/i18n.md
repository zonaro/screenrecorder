# Internacionalização (i18n)

## Visão geral

Suporte a 3 idiomas: Inglês (en), Português Brasil (pt_BR) e Espanhol (es). Implementação custom via `lib/i18n.js` + mecanismo nativo `chrome.i18n`.

## Estrutura de pastas

```
_locales/
  en/messages.json       ← fallback padrão
  pt_BR/messages.json
  es/messages.json
```

Cada `messages.json` contém ~60 chaves de tradução.

## Mecanismo (lib/i18n.js)

Módulo IIFE que exporta `I18n.init()`, `I18n.t(key, subs)`, `I18n.apply(root)`, `I18n.currentLang()`.

### init()

1. Lê `chrome.storage.local.lang`
2. Se ≠ `'auto'`, busca `/_locales/{lang}/messages.json` via `fetch()` e armazena como `overrides`
3. Se `'auto'` ou não definido, usa o idioma do browser via `chrome.i18n`

### t(key, subs)

1. Tenta `overrides[key].message` primeiro
2. Depois `chrome.i18n.getMessage(key)`
3. Suporta substituição `$1`, `$2` via regex

### apply(root)

- Traduz elementos com `data-i18n` (textContent)
- Traduz atributos com `data-i18n-attr` (formato `"placeholder|key"`)
- Service worker não tem DOM — `apply()` retorna silenciosamente

### currentLang()

Retorna o idioma ativo (`'auto'` → `chrome.i18n.getUILanguage()`).

## Uso em cada página

Cada página chama `await I18n.init()` no topo do IIFE antes de qualquer coisa. O manifest usa `__MSG_extName__`, `__MSG_extDesc__`, `__MSG_cmdToggle__`.

## Service Worker

O service worker não tem DOM — usa `chrome.i18n.getMessage()` diretamente em `uploadFlow()`.
